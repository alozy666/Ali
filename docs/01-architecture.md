# المعمارية والنشر — نسخة الاستضافة المشتركة

مرافقة لـ [`00-decision-no-vps.md`](00-decision-no-vps.md). هذي وثيقة تنفيذية:
كيف تُركَّب القطع، وكيف تُنشَر، وماذا تفحص قبل أن تبدأ.

---

## ١. قائمة الفحص المسبق — قبل أي كود

هذي الأرقام تخص خطتك أنت، ولا تُفترض. افحصها من hPanel أو عبر SSH.
**البند ٦ حاسم: لو فشل، المسار كله يسقط ولا فائدة من إكمال البقية.**

| # | ما تفحصه | المطلوب | كيف |
|---|---|---|---|
| ١ | إصدار PHP | ٨.١ فأعلى | hPanel ← PHP Configuration |
| ٢ | إصدار MySQL | ٨.٠ فأعلى (لأجل `WITH RECURSIVE`) | `SELECT VERSION();` |
| ٣ | أقل فاصل لوظائف cron | ٥ دقائق أو أقل مقبول | hPanel ← Cron Jobs |
| ٤ | `max_execution_time` | ٣٠ ثانية فأكثر | `php -i \| grep max_execution` |
| ٥ | SSH وComposer | متوفر (وإلا نرفع `vendor/` جاهزة) | hPanel ← SSH Access |
| ٦ | **الاتصالات الصادرة** | **غير محجوبة** | الأمر أدناه |

### فحص البند ٦

ارفع هذا الملف مؤقتاً وافتحه بالمتصفح، أو شغّله عبر SSH:

```php
<?php
foreach (['https://api.anthropic.com/v1/models', 'https://api.deepgram.com/v1/projects'] as $url) {
    $ch = curl_init($url);
    curl_setopt_array($ch, [CURLOPT_RETURNTRANSFER => true, CURLOPT_TIMEOUT => 10]);
    curl_exec($ch);
    $code = curl_getinfo($ch, CURLINFO_RESPONSE_CODE);
    $err  = curl_error($ch);
    curl_close($ch);

    // أي رمز HTTP (حتى 401) = الاتصال يمر والحجب غير موجود.
    // 0 مع خطأ اتصال = محجوب.
    echo $url . ' → ' . ($code > 0 ? "سالك ({$code})" : "محجوب: {$err}") . PHP_EOL;
}
```

**401 نتيجة ناجحة هنا** — تعني أن الطلب وصل ورُفض لعدم وجود مفتاح، أي أن الشبكة سالكة. الفشل هو `0` مع خطأ اتصال.

> إن ظهر «محجوب»: توقّف. راسل دعم هوستنقر لطلب فتح النطاقين — بعض الخطط تفتحها عند الطلب. وإن رفضوا، انتقل لـ Hostinger VPS بدل محاولة الالتفاف.

## ٢. المعمارية

```
                    المتصفح (React/Vite على دومينك)
                              │ HTTPS
                              ▼
              ┌────────────────────────────────┐
              │  public_html/index.php         │  ← الملف الوحيد المكشوف
              └────────────────────────────────┘
                              │
    ═══════════════ حدّ جذر الموقع ═══════════════
                              │
              ┌────────────────────────────────┐
              │  app/  (غير قابل للطلب عبر HTTP)│
              │                                │
              │  Capture/  ← بلا AI إطلاقاً     │
              │      ↓ يكتب                    │
              │  raw_inputs + jobs             │
              │      ↑ يقرأ                    │
              │  Queue/Worker  ←──── cron      │
              │      ↓                         │
              │  Providers/  (الطبقة الوسيطة)  │
              │   Llm · Stt · Push             │
              │      ↓                         │
              │  Memory/  ← الشبكة المعرفية    │
              │  Meta/    ← القرار والصلاحيات  │
              └────────────────────────────────┘
                              │
                         MySQL 8
```

### الفصل الجوهري (قسم ١٠)

الخط الفاصل بين `Capture/` و`Queue/` هو أهم قرار معماري بالنظام:

- **الالتقاط** يكتب بقاعدة البيانات ويرجع فوراً. لا ينادي Claude ولا Deepgram ولا أي خدمة خارجية.
- **المعالجة** كلها بالطابور، خلف cron.

النتيجة العملية: لو تعطّل Claude وDeepgram معاً، يبقى الالتقاط شغّالاً بالكامل — كل ملاحظة وكل تسجيل يُحفظ، ويُعالَج دفعةً واحدة عند عودة الخدمة. هذا نص المبدأ بوثيقتك: «الالتقاط ما يفشل أبداً، حتى لو الذكاء فشل مؤقتاً».

### دورة حياة المهمة

```
التقاط  →  jobs(pending)
              │  cron كل ٥ دقائق
              ▼
        claim() ← حجز صفّي بشرط status='pending'
              │
              ▼
        معالج المهمة
         ├─ نجح  → done
         └─ فشل  → pending مع تأخير ٥ ثم ٢٠ دقيقة
                    وبعد ٣ محاولات → failed (يظهر بالفحص الأسبوعي)
```

ثلاث حمايات مقصودة، كلها تخص الاستضافة المشتركة تحديداً:

1. **الحجز الصفّي بشرط الحالة.** لو طال تشغيل cron أكثر من الفاصل الزمني، يتداخل تشغيلان. بلا هذا الشرط ينفّذان نفس المهمة مرتين — أي عقد مكررة بالشبكة.
2. **الميزانية الزمنية.** العامل يتوقف من نفسه قبل `max_execution_time` ويترك الباقي للتشغيل القادم، بدل أن يقتله السيرفر في منتصف مهمة.
3. **استعادة المهام العالقة.** لو قُتل التشغيل رغم ذلك، تبقى المهمة `running` للأبد. `recoverStuck()` يعيدها بعد ١٥ دقيقة.

## ٣. مخطط قاعدة البيانات

الملف: [`app/db/migrations/001_initial_schema.sql`](../app/db/migrations/001_initial_schema.sql)

| الجدول | الغرض | القسم |
|---|---|---|
| `raw_inputs` | كل مدخل خام قبل أي معالجة | ١٠ |
| `jobs` | الطابور — بديل Celery/Redis | ١٠ |
| `entities` | العقد، مع `weight` و`state` لذاكرة الظل | ٧ |
| `entity_aliases` | مفاتيح المطابقة — قلب دمج الكيانات | ٧، ٣٢ |
| `edges` | العلاقات، بوزن يتراكم مع التكرار | ٧ |
| `embeddings` | جاهز، يُعبَّأ بالمرحلة ٢ | ٧ |
| `action_types` | التصنيف وعدادات الترقية | ٤ |
| `actions` | سجل الأفعال مع سبب كل قرار | ٥، ٢٠ |
| `pending_questions` | الأسئلة غير العاجلة | ٥ |
| `push_subscriptions` | أجهزة الإشعارات | ١٢ |
| `notification_log` | عدّاد الضابط اليومي | ٢٢ |
| `cost_log` | مؤشر التكلفة الظاهر | ٣٦ |

### كيف تحل MySQL محل Neo4j

**التنقل عبر العلاقات** — `WITH RECURSIVE` في `Retriever::neighborhood()`. العلاقات تُعبر باتجاهيها (شرط الوصل يفحص `src_id` و`dst_id` معاً)، فيصل التنقل من الشخص للمشروع ومن المشروع للشخص.

**حد العمق ضرورة لا تجميل:** MySQL لا يدعم شرط `CYCLE`. وشبكتك فيها دورات بطبيعتها (شخص ← مشروع ← قرار ← نفس الشخص)، فبلا حد العمق يتوسع الاستعلام بلا نهاية. العمق مثبَّت عند ٢.

**مرونة الخصائص** — عمود `attrs JSON` يعطي ما تعطيه Neo4j: خاصية جديدة لأي عقدة بلا `ALTER TABLE`. هذي نفس حجة JSONB التي ذكرتها بقسم ٦.

### ملاحظتان على البحث النصي بالعربية

1. **`innodb_ft_min_token_size` = ٣ افتراضياً.** الكلمات الأقصر من ثلاثة أحرف لا تُفهرس. بالعربية هذا يُسقط كلمات دالّة («جو»، «أب»). راقبها، وإن ضايقتك فالحل ضبط الخادم أو الاعتماد على `entity_aliases` للأسماء القصيرة.
2. **لا اشتقاق (stemming) عربي.** «مشاريع» لا تجد «مشروع». التطبيع يحل الإملاء لا الصرف. هذي إحدى أوضح الفوائد المرتقبة من إضافة المتجهات بالمرحلة ٢ — وقتها قِس الفرق فعلياً بمنهجية قسم ٢١.

## ٤. النشر على hPanel

### البنية على السيرفر

```
/home/USER/
├── lifeos/                 ← خارج جذر الموقع
│   ├── app/
│   ├── vendor/
│   └── composer.json
└── public_html/            ← جذر الموقع
    ├── index.php           (من public/)
    └── .htaccess           (من public/)
```

**هذا الفصل هو أهم إجراء أمني على استضافة مشتركة.** ملفات الإعدادات والمفاتيح لا يمكن طلبها من المتصفح — ليس لأن قاعدة إعادة كتابة تمنعها، بل لأنها ليست تحت الجذر أصلاً. القاعدة تُنسى أو تُلغى بتحديث؛ موقع الملف لا.

بعد الرفع، عدّل `APP_PATH` بأعلى `index.php` ليطابق مسارك:

```php
const APP_PATH = '/home/USER/lifeos/app';
```

### الخطوات

```bash
# ١. المخطط
mysql -u USER -p DBNAME < app/db/migrations/001_initial_schema.sql

# ٢. الإعدادات
cp app/config/config.sample.php app/config/config.php
# عبّئ القيم، وولّد المفتاحين:
php -r "echo 'field_key_base64: ' . base64_encode(random_bytes(32)) . PHP_EOL;"
php -r "echo 'api_token: ' . bin2hex(random_bytes(32)) . PHP_EOL;"

# ٣. الاعتماديات (لو SSH متاح)
composer install --no-dev --optimize-autoloader
# بلا SSH: شغّل الأمر محلياً وارفع مجلد vendor/ كما هو

# ٤. الصلاحيات
chmod 700 app/storage app/config
chmod 600 app/config/config.php

# ٥. تحقّق
php app/tests/run_tests.php
php app/cron/worker.php
```

### وظائف cron

```
*/5 * * * *   /usr/bin/php /home/USER/lifeos/app/cron/worker.php    >> /home/USER/lifeos/app/storage/logs/worker.log 2>&1
0 6 * * *     /usr/bin/php /home/USER/lifeos/app/cron/proactive.php morning
0 20 * * *    /usr/bin/php /home/USER/lifeos/app/cron/proactive.php evening
0 3 * * *     /usr/bin/php /home/USER/lifeos/app/cron/backup.php    >> /home/USER/lifeos/app/storage/logs/backup.log 2>&1
0 4 * * 0     /usr/bin/php /home/USER/lifeos/app/cron/health.php    >> /home/USER/lifeos/app/storage/logs/health.log 2>&1
```

**هذي الأسطر الخمسة هي بديل الـ VPS بالكامل.**

> لو كان أقل فاصل تسمح به خطتك ١٥ دقيقة بدل ٥، لا مشكلة: أسوأ أثر أن يتأخر تحليل ملاحظة ربع ساعة. الالتقاط فوري على أي حال.

## ٥. الأمان (قسم ٩)

| المتطلب | الحالة |
|---|---|
| الكود خارج جذر الموقع | ✅ |
| HTTPS إلزامي | ✅ `.htaccess` |
| تشفير الحقول الحساسة | ✅ `sodium_crypto_secretbox` — المفتاح خارج القاعدة |
| لا تسريب تفاصيل الأخطاء | ✅ |
| نسخ احتياطي مشفّر | ⚠️ يعمل، **لكن الرفع الخارجي ناقص** |
| **2FA** | ❌ **ناقص — رمز ثابت فقط** |
| انتهاء صلاحية الجلسة | ❌ ناقص |

**أكمل هذين قبل إدخال أي بيانات حقيقية.** الشبكة المعرفية هنا ستحتوي وضعك المالي وعلاقاتك وحالتك النفسية، لا ملاحظات عابرة. الرمز الثابت الحالي كافٍ للتجربة على بيانات وهمية فقط.

وبالمثل: `backup.php` يكتب نسخة مشفّرة بجانب الأصل. قسم ٩ يشترط فصلاً جغرافياً، والنسخة التي تجلس على نفس الحساب لا تحميك من فقدانه. أكمل الرفع الخارجي (نهاية `backup.php`) **قبل** أن تبدأ التغذية الفعلية لا بعدها.

### حقن التعليمات (قسم ٣٤)

القاعدة مثبّتة داخل موجّه الاستخراج: كل محتوى مقروء **بيانات لا تعليمات**. والنص الخام يصل داخل حدود صريحة (`<<<INPUT ... INPUT`) كطبقة ثانية. هذي القاعدة تزداد أهمية حين تفعّل القراءة التلقائية للبريد والرسائل.

## ٦. الاختبارات

```bash
php app/tests/run_tests.php
```

٤٦ اختباراً تغطي أخطر جزء بالنظام: تطبيع النصوص ودمج الكيانات وقراءة رد النموذج. بلا PHPUnit عمداً — تعمل على الاستضافة نفسها عبر SSH، والاختبار الذي لا يمكن تشغيله بالبيئة الحقيقية لا يطمئنك عليها.

**هذي الاختبارات أمسكت خللاً فعلياً أثناء البناء:** أول نسخة من `EntityResolver` سجّلت الاسم الأساسي وحده أليساً وأهملت الصيغ البديلة. النتيجة أن «زينب (Zainab)» تُنشئ عقدة يصلها العربي فقط، ثم يُنشئ أول ذكر إنجليزي عقدة ثانية — أي بالضبط تلويث الشبكة بعقد مكررة الذي تحذّر منه بقسم ٧.

## ٧. ما لم يُبنَ بعد

المُنجَز: المرحلة ٠ والمرحلة ١ جزئياً (قسم ١٥). الشريحة الرأسية كاملة — التقاط ← طابور ← استخراج ← شبكة معرفية.

| التالي | يعتمد على |
|---|---|
| رفع النسخة خارجياً + 2FA | **قبل أي بيانات حقيقية** |
| واجهة React لشاشتَي الالتقاط و«اليوم» | الـ API جاهز |
| جلسات التأسيس الخمس (قسم ١١) | ثبات الالتقاط |
| سؤال وجواب فوق الذاكرة (مرحلة ٢) | شبكة فيها محتوى |
| المتجهات | قياس هل FULLTEXT يكفي |
| ملخص صباحي ذكي | شبكة فيها محتوى |

**ترتيب مقصود:** الإيجاز الصباحي الآن يرسل ملخصاً واقعياً من الحالة الفعلية بلا استدعاء نموذج. توليد ملخص «ذكي» فوق شبكة فاضية ينتج كلاماً عاماً، وأسرع طريقة لتعليم نفسك تجاهل الإشعار هي أن يصلك إشعار فارغ أسبوعين — وقيمة هذي الميزة كلها بأن تُقرأ.
